# Epic 0 Retrospective — Toolchain

**Date:** 2026-04-25
**Epic:** 0 — Toolchain (Pre-epic, Dev-Only)
**Stories:** 4 (all done)

## Summary

Epic 0 established the project foundation: tech stack validation, crate restructuring, code hygiene, and test infrastructure. No user-facing value — purely developer infrastructure.

## What Went Well

- **std::thread over tokio**: Spike confirmed std::thread produces a 4.2MB binary vs 15MB for tokio (3.6x smaller), with 13 fewer dependencies. Correct decision validated quantitatively.
- **GTK4 0.11 upgrade**: Successfully migrated from gtk4-rs 0.8 to 0.11 with v4_14 feature flag. Cold build time 51s verified in spike.
- **Flat module hierarchy**: Workspace with 5 sub-crates collapsed to single crate with flat module structure. Simplified dependency management.
- **check-patterns.sh**: Automated enforcement for clippy, unwrap checks, import rules, and tests keeps quality consistent.
- **MockMpdServer**: 3 smoke tests pass without external MPD dependency — enables deterministic testing.

## Challenges

- **Crate restructure complexity**: `git mv` across crates required careful handling of `use` paths and pub mod declarations. Multiple build iterations needed.
- **Module import rules**: Enforcing `mpd/` never imports `ui/` and `presenters/` never imports `mpd/` directly requires vigilance — compile-time verification only catches direct imports.
- **Edition 2024**: Some Rust 2024 edition changes (e.g., `gen` is now a keyword) caused compilation surprises in later stories.

## Key Insights

- **Spike-before-implement pattern works**: Validating GTK4 versions, binary sizes, and dependency trees before committing to production code prevented wrong choices.
- **Single binary vs workspace**: Going single-crate reduced build complexity but means all tests must pass together — no per-crate isolation.
- **Release/Acquire ordering**: Code review caught `Ordering::Relaxed` on stop flags — needs explicit memory ordering for ARM compatibility.
